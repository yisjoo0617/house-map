# House-Map 기획 · 설계서

부동산 내부 촬영 영상 우측 하단에 **칠판 스타일 도면 + 현재 있는 방(빛나는 마커)** 미니맵을 합성하는 웹 도구.

> **v2 변경 (2026-09-19, 레퍼런스 스크린샷 반영)**
> - 위치는 **방 단위**로만 표시합니다. 방 안의 세부 움직임, 경로 트레일, 시야 방향은 표시하지 않습니다.
> - 디자인: 어두운 칠판 배경, 흰 분필 선 도면, 손글씨 제목 "OOO mini map 1F", 하단 안내문, 빛 번짐 원형 마커.
> - 복층을 지원합니다(층별 도면, 층 전환 시 도면과 층 표시 교체).
> - 입력 방식: 도면에 방 위치를 찍고, 영상을 보면서 방에 들어가는 순간 숫자키를 누릅니다.
> - AI(광학 흐름)는 이동 시점 추천에만 씁니다.
> 아래 1장의 "키프레임 사이 보간" 설계는 v1 기록으로 남겨 둡니다.

## 1. 타당성 검토 (AI로 가능한가?)

| 접근 | 방법 | 정확도 | 비용/난이도 | 판단 |
|---|---|---|---|---|
| A. 영상만으로 도면 자동 생성 | 단안 SLAM/3D 복원(MASt3R-SLAM, DROID-SLAM, DPVO) → 포인트클라우드 → 평면 투영 → 벽 추출(RoomFormer 등) | 중~하 (스케일 불명확, 흰 벽·유리·거울에서 실패 잦음) | GPU 필수, 영상당 수 분~수십 분 | **2단계(R&D)** |
| B. 영상만으로 위치 자동 추정 + 기존 도면에 정합 | 비주얼 오도메트리로 궤적 추출 → 도면에 스케일/회전 정합 | 중 (누적 드리프트, 스케일 모호) | GPU 권장 | 2단계 |
| **C. 사용자 도면 + 키프레임 + CV 보정 (채택)** | 사용자가 몇 개 시점에서 도면 위 위치를 클릭 → 광학 흐름(Optical Flow)으로 "걷는 중/멈춤"과 "고개 회전"을 분석 → 키프레임 사이 경로를 움직임에 맞춰 보간 | **상** (키프레임이 드리프트를 매번 보정) | CPU만으로 동작 | **1단계(MVP)** |

**결론**: 완전 자동은 현재 기술로 실사용 품질을 보장하기 어렵다. 사용자가 이미 제공할 수 있는 **도면 + 출발 시점 + 시점 프레임(키프레임)** 을 뼈대로 쓰고,
AI/컴퓨터비전은 **키프레임 사이를 자연스럽게 채우는 역할**(이동 속도, 정지 구간, 시야 방향)로 쓰는 것이 품질·비용 모두 최적이다.
영상 1개당 키프레임 5~15개(방 이동·문 통과 시점) 정도면 충분하다.

### 사용 기술 / 라이브러리

| 역할 | 라이브러리 | 비고 |
|---|---|---|
| 웹 서버 / API | FastAPI + Uvicorn | 업로드, 작업 큐, 다운로드 |
| 영상 분석 | OpenCV (`calcOpticalFlowPyrLK`, `estimateAffinePartial2D`) | 이동량·회전(yaw) 추정, 장면 전환 감지 |
| 경로 보간 | NumPy (Centripetal Catmull-Rom + 호 길이 재매개화) | 벽을 덜 가로지르는 부드러운 곡선 |
| 영상 인코딩 | FFmpeg (`imageio-ffmpeg` 번들 바이너리) | H.264 합성본, ProRes 4444(알파) 오버레이 |
| 프론트엔드 | Vanilla JS + Canvas | 빌드 도구 없이 동작, 실시간 미리보기 |

2단계 후보: MASt3R-SLAM / DROID-SLAM(궤적 자동 추정), RoomFormer(도면 벡터화), Claude 비전 API(프레임→"어느 방인지" 자동 추천).

### 언어 선택: **Python**
영상 처리(OpenCV), AI 모델(PyTorch 계열 SLAM), FFmpeg 연동 생태계가 모두 파이썬 중심이다. 프론트는 브라우저 표준 JS로 충분하다. Java는 영상/AI 라이브러리가 빈약해 불리하다.

## 2. 기능 기획 (v2)

### 사용자 흐름
1. **프로젝트 생성**: 영상과 층별 도면 이미지를 업로드하면 도면의 흰 여백을 자동으로 잘라냅니다.
2. **방 찍기**: 도면의 빈 곳을 클릭하고 방 이름을 입력합니다.
3. **이동 기록**: 재생 중 방에 들어가는 순간 숫자키 1~9를 누릅니다. 방을 클릭하거나 방 버튼을 눌러도 됩니다. 타임라인에서 드래그로 시각을 조정할 수 있습니다.
4. **AI 이동 시점 추천**: 광학 흐름으로 멈춤과 장면 전환을 찾아 타임라인에 표시합니다.
5. **미리보기**: 서버가 그린 패널 이미지와 마커로 그리기 때문에 최종 결과와 똑같습니다.
6. **렌더링과 다운로드**: `composite.mp4`, `overlay.mov`(투명 ProRes 4444), `minimap_<층>.png`, `project.json`

### 미니맵 표시 요소
- 칠판 배경(대각선 음영), 분필 질감의 선 도면, 손글씨 제목과 층 표시, 하단 안내문
- 빛 번짐 원형 마커: 방을 옮길 때 부드럽게 이동하고, 층이 바뀌면 즉시 전환합니다.
- 설정 항목: 스타일(칠판/원본), 색상, 선 인식 강도, 글꼴, 이동 효과와 시간, 위치, 크기, 불투명도

## 3. 시스템 설계 (v2)

```
[Browser: index.html / app.js]
   │ 업로드, 방·이동 기록 편집, 미리보기(서버가 렌더링한 패널 PNG + 마커 스프라이트)
   ▼
[FastAPI app/main.py] ── data/projects/<id>/ (video, plan_f*.png, project.json, analysis.json, outputs/)
   ├─ app/track.py   : rooms + events → 프레임별 (floor, x, y)
   ├─ app/render.py  : 칠판 패널 생성, 마커, FFmpeg 인코딩
   └─ app/motion.py  : 광학 흐름 → 이동 시점 추천
```

### 데이터 모델 (project.json)
```json
{ "floors": [{"id": "f1", "label": "1F", "file": "plan_f1.png"}],
  "rooms":  [{"id": "r1", "name": "거실", "floor": "f1", "x": 650, "y": 500}],
  "events": [{"t": 0.0, "room": "r1"}, {"t": 12.4, "room": "r2"}],
  "settings": { "style": "chalk", "transition": "slide", "transition_sec": 0.8 } }
```

### 핵심 알고리즘
- **칠판 변환**: 회색조 값이 기준값보다 어두운 픽셀만 선으로 인정합니다(컬러 바닥재나 가구 채색 제거). 축소 후 대비를 보정하고, 노이즈 텍스처를 곱해 분필 질감을 냅니다.
- **방 이동**: 기록 시각을 중심으로 `transition_sec` 동안 smoothstep 곡선으로 이동합니다. 이전 이동과 겹치지 않게 하고, 층이 바뀌면 즉시 전환합니다.
- **마커**: 4배로 크게 그린 뒤 축소한(premultiplied) RGBA 스프라이트입니다. 가우시안 빛 번짐, 흰 원, 회색 링으로 구성됩니다.

### API
| Method | Path | 설명 |
|---|---|---|
| POST | `/api/projects` | video, plans[], name, labels로 프로젝트 생성 |
| GET/PUT/DELETE | `/api/projects/{id}` | 조회 / 방·이동 기록·설정·층 이름 저장 / 삭제 |
| POST/DELETE | `/api/projects/{id}/floors[/{fid}]` | 층 추가 / 삭제 |
| GET | `/api/projects/{id}/minimap` | 미리보기용 패널 PNG와 레이아웃, 마커 |
| GET | `/api/projects/{id}/track?fps=30` | 프레임별 (floor, x, y) |
| POST | `/api/projects/{id}/analyze` | 이동 시점 추천 분석 |
| POST | `/api/projects/{id}/render` | 렌더링 (composite / overlay / minimap) |
| GET | `/api/jobs/{job_id}` | 작업 진행률 |
| GET | `/api/projects/{id}/files/{name}` | 원본과 결과 다운로드 |

## 6. Vercel 배포 검토 (2인 사용)

**결론: 지금 구조 그대로는 Vercel에 올릴 수 없습니다.** Vercel은 정적 사이트와 짧은 서버리스 함수에 맞춰진 서비스라서, 이 앱의 핵심 작업(대용량 영상 업로드, 수십 초 이상 걸리는 렌더링, 파일 저장)과 맞지 않습니다.

Vercel 공식 문서(2026-09 확인) 기준 **Hobby(무료) 플랜**과 비교한 결과입니다.

| 항목 | Hobby 제한 | 이 앱의 실측 / 필요량 | 판정 |
|---|---|---|---|
| 사용 목적 | **비상업, 개인 용도만 허용** (fair use guidelines) | 유튜브 채널 콘텐츠 제작용 | 수익 창출 채널이면 약관 위반 소지 |
| 업로드 | 함수 요청 본문 최대 4.5MB | 영상 1.5GB | 직접 업로드 불가 |
| 우회 저장소 (Vercel Blob) | 무료 저장 용량 월 평균 1GB | 영상 1개가 1.5GB | 영상 1개도 보관 불가 |
| 함수 실행 시간 | 최대 300초 | 22코어 PC 기준: 재생용 영상 47초, 분석 36초, 렌더링 24초 | 함수는 1 vCPU라 몇 배 느려져 300초 초과 가능성 큼 |
| CPU / 메모리 | 1 vCPU, 2GB, 월 Active CPU 4시간 | 영상 처리는 CPU를 많이 씀 | 몇 편 만들면 한도 소진 |
| 파일 저장 / 작업 큐 | 영구 디스크 없음, 요청이 끝나면 종료 | 프로젝트 폴더, 백그라운드 작업 | 구조 변경 필요 |
| 한도 초과 시 | 해당 기능 30일 사용 정지 | | |

### 선택지
1. **내 PC + 터널 (추천, 무료, 코드 변경 없음)**: Cloudflare Tunnel이나 Tailscale로 내 PC의 서버를 친구에게만 공개합니다. 내 PC가 켜져 있어야 하고, 간단한 비밀번호 인증을 하나 추가하는 것이 좋습니다.
2. **컨테이너 호스팅 (월 5~10달러)**: Railway, Render, Fly.io 등에 Docker로 지금 코드를 그대로 올리고, 영구 볼륨과 비밀번호를 추가합니다.
3. **Vercel용 재설계 (개발 규모 큼)**: 오버레이는 원본 영상을 디코딩할 필요가 없어서 이 방식도 가능합니다.
   - 영상은 업로드하지 않고 브라우저에서 로컬 파일로 재생합니다.
   - 칠판 도면 변환과 오버레이 인코딩을 브라우저에서 합니다(OpenCV.js, ffmpeg.wasm의 qtrle).
   - Vercel에는 정적 페이지와 프로젝트·프리셋 JSON만 둡니다(Vercel Blob/KV).

   서버 비용이 거의 없고 업로드도 필요 없지만, 렌더링 파이프라인을 JS로 다시 작성해야 합니다.

2인 사용이라면 **1번으로 시작**하고, 실제로 자주 쓰게 되면 3번을 검토하는 것을 권장합니다.
